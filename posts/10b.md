## Trying Out Ruby2D

I decided to try out Ruby2D. I’ve used JavaScript and p5.js a decent amount this semester between my two coding classes, so I was curious to explore a different scripting language that still focuses on visuals and interactivity. Ruby2D stood out because it's designed for making visual things quickly, and I hadn’t touched Ruby before, so it felt like a good excuse to experiment.

### Getting Started

I followed along with this tutorial series:  
[https://www.ruby2d.com/learn/](https://www.ruby2d.com/learn/)

It walks through installing Ruby, setting up Ruby2D, and running your first scripts. The process was smooth. Once everything was installed, I could just write a .rb file and run it in the terminal to see graphics appear in a window.

Here’s a simple script I made while playing around:

```ruby
require 'ruby2d'

set background: 'black'

circle = Circle.new(
  x: 200, y: 200,
  radius: 50,
  sectors: 32,
  color: ['red', 'orange', 'yellow']
)

update do
  circle.x += 1 if circle.x < Window.width
end

show
```

This just creates a rainbow circle that slowly slides across the screen. It’s basic, but it helped me get how Ruby2D handles objects, animation, and drawing.

## Why Ruby2D?

I liked Ruby2D because it reminded me of early p5.js stuff, where the focus is on play and experimentation. There’s not a huge setup or build process. You write a few lines and something visual happens. I also found the Ruby syntax super readable. It’s not too picky and feels beginner friendly without being overly simple.

## How I Might Use It

I could see myself using Ruby2D for sketching out small visual ideas or interactive experiments. Since it runs on the desktop, it’s probably not what I’d use for web-based work, but for standalone pieces or installations it could work well. If I wanted to do a lo-fi, offline version of my Summer Games aura visualiser, Ruby2D might be a cool tool to try.

## Strengths and Weaknesses

Strengths of Ruby2D:

- Simple and fast to prototype ideas
- Easy setup
- Very readable and beginner friendly
- Nice support for 2D shapes, animation and interaction

Weaknesses:

- Not usable in the browser (which I like)
- Smaller community makes troubleshooting issues down the line a bit harder
- Not as scalable for big projects

## Scripting vs Compiled Languages

Scripting languages like Ruby, JavaScript or Python are great for quick iteration. You don’t have to compile anything. You just write, save and run. That makes them perfect for creative coding and experimentation. The downside is they can be slower and aren’t ideal for heavy performance-based work.

Compiled languages like C++ or Rust are faster and offer more control, but they come with more setup and maintenance. For art and design work, I usually want to move fast and try things, so scripting languages make more sense.

In terms of my own creative practice and this idea of mycelial creativity, scripting languages allow for branching, forking, remixing and playing with complexity. Things grow and shift easily, like little digital fungi spreading across the forest floor. It’s less about precision and more about letting things evolve.
